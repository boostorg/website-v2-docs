* boost_phrase:library[Asio,/libs/asio/]
** Added `eager`, a completion token that starts an asynchronous operation immediately and allows its result to be waited on later.
** Added `trampoline<>` and `make_trampoline()`, an executor adapter that runs nested submissions in a bounded thread-local queue, rather than resubmitting them to the target executor.
** Added `execution::staging_executor` and `execution::stage()`, to reduce the cost of `require`/`prefer` chains on polymorphic executors.
** Added overloads of `cancel_after` that cancel an operation when a "trigger" asynchronous operation completes.
** Added support for sending and receiving multiple datagrams in a single call.
** Promoted `channel` and `concurrent_channel` from the `experimental` namespace, added `can_send` and `can_receive` to the channel
classes, and added `try_peek` to `basic_channel`.
** Added an optional "spin" reactor backend that avoids demultiplexing system calls such as `epoll_wait` by polling descriptors directly.
** Added the `descriptor_name` I/O control command, for per-descriptor configuration.
** Added a Perfetto-format handler tracking backend.
** Added a dependency-free `spawn()` implementation for Linux and macOS on x86-64 and AArch64, which may be explicitly enabled.
** Added `awaitable` to the forward declarations in `boost/asio/fwd.hpp`.
** Added support for `final` allocator types to the `io_context` executor.
** Added an associated executor to `experimental::promise`pass:['s] wait operation.
** Changed custom handler tracking so that `BOOST_ASIO_HANDLER_CREATION` may be called without the execution context argument.
** Changed `poll()` to bound the amount of work performed per call.
** Optimised the scheduler, coroutines, completion handling, polymorphic executors, the reactor and the recycling allocator, and reduced the size of the `thread_pool` executor.
** Optimised `read_until` and `async_read_until` when used with a character delimiter.
** Fixed a potential deadlock in the reactor when completing operations during shutdown or after a descriptor error.
** Fixed a use-after-free when destroying a nested `any_completion_handler`.
** Fixed `cancel_after` and `cancel_at` with reentrant cancellation.
** Fixed `spawn()` when the coroutine completes immediately.
** Fixed pending channel sends being lost on close, and `try_send*` when used with multiple signatures.
** Fixed the associator binder and work dispatcher move constructors.
** Fixed duplicate work counting with a polymorphic I/O executor.
** Fixed the `async_connect` continuation hooks.
** Fixed `experimental::ranged_parallel_group` with operations that have no associated executor.
** Fixed IOCP wake-up packet accumulation, `stream_file` position accounting, and 4 GiB buffer truncation on Windows.
** Fixed iteration over empty resolver results.
** Fixed `multicast::enable_loopback` for IPv6 on Solaris and illumos.
** Fixed thread sanitizer support on older toolchains.
** Fixed compilation without `SA_RESTART` or with bounds safety attributes enabled.
** Fixed warnings on clang-cl, OpenBSD and illumos.
** Consult the boost_at:/doc/libs/1_93_0/doc/html/boost_asio/history.html[Revision History] for further details.

* boost_phrase:library[Container,/libs/container/]:
** Containers now accept allocators whose `value_type` is `void`; such allocators are rebound to
   the container's element type via `real_allocator`.
** Added overaligned support for `pmr::monotonic_buffer_resource`.
** The library is again fully header-only. Global variables and functions that were moved to the
   separately compiled library now live in an intermodule utility that can share them across DLLs.
** Dlmalloc's heap now always uses an improved, spin lock and small allocation layout, with faster
   allocation for small requests (240-512 bytes are ~15-25% faster on 64-bit).
** Counted `basic_string` constructors and member functions accept a null pointer when the count is
   zero (LWG 2235 and the {cpp}20 "valid range" wording).
** Iterators, stateless allocators, `pmr::polymorphic_allocator`, `scoped_allocator_adaptor` and
   internal utilities are trivially copyable when their members are. This allows some compilers to
   pass and return them in registers.
** Allocator-extended move constructors are now `noexcept` when
   `allocator_traits<Allocator>::is_always_equal` is true (as an extension to the standard) in
   `vector`, `devector`, `deque`, `segtor`, `list`, `slist`, `stable_vector`, `basic_string` and
   `hub`. `map`, `multimap`, `set` and `multiset` also need a comparator with a non-throwing copy
   constructor and swap.
** `devector`: the `relocate_never` option, documented in previous releases, is now implemented.
   The elements are never relocated inside the buffer: an insertion at a full end always allocates
   a new buffer. With this option `push_back`, `push_front`, `emplace_back` and `emplace_front` give
   the strong exception guarantee.
** Fixed bugs/issues/enhancements:
*** Error on instantiating an incomplete type (boost_gh:issue[container,335]).
*** Optimized range insertion for `boost::container::hub` (boost_gh:pr[container,339]).
*** Using unqualified `swap()` on two `small_vector`pass:[s] calls an incorrect swap function
    (boost_gh:issue[container,342]).
*** `default_init` results in a `memset` with GCC16 (boost_gh:issue[container,333]) (documented,
    see the note in "Default initialization" in the documentation).
*** Build break on Windows ARM64EC near the definition of the `BOOST_CONTAINER_PREFETCH` macro
    (boost_gh:issue[container,344]).
*** Regression: invalid assertion in string assign (and probably other functions)
    (boost_gh:issue[container,346]).
*** `vector<X>::erase()`-from-middle leaks for `X` in `basic_string`, `deque` and `stable_vector`
    (boost_gh:issue[container,351]).
** A systematic, AI-assisted review of the library found and fixed many bugs that users did not
   report. The main types of bugs are:
*** Exception safety: memory leaks and lost nodes when a comparator, a constructor or an allocation
    throws or incorrect rollback on insertions.
*** `noexcept` specifications: incorrect conditions in move constructors and move assignments of
    `vector`, `small_vector`, `static_vector`, `devector`, `set` and `map`, and functions that can
    throw but were marked `noexcept`.
*** Allocator propagation: `small_vector` move and swap with unequal allocators, `vector` move
    assignment.
*** Integer overflow and size limits.
*** Class template argument deduction for `stable_vector`, `deque`, `list`, `slist`, `basic_string`
    and `nest`.
*** Complexity: quadratic insertion in `stable_vector` and `deque`, and a non-linear `erase_if` in
    flat containers.

** In {cpp}20, made `to_string()`, the string constructors and the `find_*()` functions usable in

** Fixed several issues with user-supplied containers and allocators (e.g. `std::deque` and
   `std::pmr::polymorphic_allocator`), and documented the requirements on a container.
** Made `append()` of a range of blocks give the strong exception guarantee, and made a
   moved-from bitset, and one whose copy or move assignment throws, always empty.
** Made loading from a Boost.Serialization archive check the data, and throw
   `std::invalid_argument` if it is invalid.
** Fixed link errors with `npos` and `bits_per_block` in {cpp}11 and {cpp}14, a regression of

** Made faster the bitwise and shift operators, `set()`, `reset()` and `flip()` of a range, the

*** `managed_shared_memory` can't allocate a chunk of more than half its allocation any more
    (boost_gh:issue[interprocess,250]).

* boost_phrase:library[Intrusive,/libs/intrusive/]:
** Added `unordered_bucket_manager` utility.
** `get_parent_from_member` and member hooks now support parents with virtual bases (as long as the
   member is not located in a virtual base) and the `/vmg` (full generality pointer to member
   representation) compiler option in MSVC ABI compatible compilers.
** Iterators and comparator holders no longer declare user-provided copy operations, so they are
   trivially copyable when their members are. This way, compilers can pass and return them in
   registers instead of by hidden reference.
** Fixed functions calling predicates and/or hashes that were incorrectly marked as `noexcept`.
** Move constructors now copy the predicates (comparison, priority, hash and equality) instead of
   moving or swapping them, as standard containers do
   (https://cplusplus.github.io/LWG/issue2227[LWG 2227]), so the moved-from container keeps valid
   predicates. They are `noexcept` when those copies (and the copies or moves of the value and
   bucket traits) are `noexcept`.
** **Potentially breaking change**: move assignments no longer swap the containers. As in standard
   containers, the elements of the target are unlinked (as `clear()`), the predicates of the source
   are copied, its nodes are linked to the target and the source is left empty. In unordered
   containers the target takes the bucket array of the source, which is left without one, and no
   longer uses its own. The move assignments are `noexcept` when the copies of the predicates and
   the moves of the value and bucket traits are `noexcept`. Define
   `BOOST_INTRUSIVE_MOVE_ASSIGNMENT_SWAPS` to get the old behavior during a transition period: the
   macro will be removed in a future release. See "Moving and Swapping Boost.Intrusive containers"
   in the documentation for more information.
** Move constructors and move assignments of all containers now move the value traits. Before, the
   behavior was not specified and it was not consistent: unordered containers moved them, tree
   containers copied them, and `list` and `slist` swapped them in the move assignment. As for
   allocators in standard containers, a move of the value traits must leave the source equal to the
   result, so a moved-from container keeps valid value traits. The `noexcept` conditions of the
   move operations check these moves. See "Stateful value traits" in the documentation.
** **Potentially breaking change**: treap containers no longer accept `auto_unlink` hooks (a static
   assertion is raised), as unlinking a node through the hook broke the heap order of the
   priorities, so it was a bug.
** **Potentially breaking change**: `suggested_lower_bucket_count(n)` now returns the biggest
   supported bucket count that is smaller than or equal to `n` (previously it returned the smallest
   one bigger than or equal to `n`) and `suggested_upper_bucket_count(n)` now returns `n` if `n` is
   a supported bucket count (previously it returned the next one), as documented. If the value does
   not fit in `size_type`, both functions now return the biggest supported bucket count that
   `size_type` can represent, instead of a truncated or saturated value that was not valid for
   `fastmod_buckets`.
** Optimized:
*** `reverse` operations for lists.
*** splay tree algorithms/containers, taking advantage of splaying operations to reduce
    comparisons for unique keys and insertions with hints.
*** tree iteration primitives and some other operations like `is_header`.
*** `clear_and_dispose` for tree containers, as nodes are no longer initialized twice in safe and
    auto-unlink modes.
*** `merge_unique` and `merge_equal` for tree containers when both containers use the same
    comparison type and this type is an empty class.
** A systematic, AI-assisted review of the library found and fixed many bugs that users did not
   report. The main types of bugs are:
*** Exception safety: `clone_from` rollback when the cloner throws, a `linear_buckets` hash table
    left without its sentinel when a rehash throws, and `noexcept` specifications and documented
    exception guarantees of functions that call user predicates, hashers or comparators.
*** Stateful value traits and predicates: swap and move assignment did not swap or propagate the
    value traits, and cloning did not transfer the predicates, comparators and hashers correctly.
*** Container invariants: `slist::splice_after` with `cache_last`, `slist::incorporate_after` with
    `constant_time_size`, `slist::dispose_and_assign`, linear `slist::sort`, `swap_nodes` of
    circular slist algorithms, leftmost and rightmost nodes in `clone_subtree`, cloning from empty
    trees, self merge, and `rebalance()` of red-black, AVL and treap trees (removed, as it broke the
    invariants).
*** Unordered containers: the cached begin after a rehash, `erase(first, last)` and full rehash
    with `optimize_multikey`, `clone_from` with `fastmod_buckets`, `operator==`, moved-from
    containers that were not usable, and `floor_log2` on MSVC ARM64.
*** Lookups: `count(key, comp)` in unique key containers with a coarser comparison, `splay_down`
    that ignored the comparator, and extra comparisons in `list::merge` and `slist::merge`.
*** Compilation errors with function pointer predicates, smart pointers, `last()` and `clone_from`
    with rvalues.

* boost_phrase:library[Move,/libs/move/]:
** Fixed stability bugs both in `adaptive_merge` and `adaptive_sort`.
** Significantly improved performance of adaptive algorithms. Up to 4x faster in some corner cases.

   when the macro is defined (define `BOOST_ALLOW_DEPRECATED` or `BOOST_ALLOW_DEPRECATED_SYMBOLS`
   to remove it).
** `unique_ptr` changes:
*** `unique_ptr` is now marked with the `trivial_abi` attribute when the compiler supports it
    (Clang targeting Itanium ABI), so it is passed and returned in registers. This changes the
    calling convention so it must be consistent when passing across translation units. Define
    `BOOST_MOVE_DISABLE_TRIVIAL_ABI` to keep the old calling convention.
*** Fixed `unique_ptr` bugs that were non-standard.
*** Added full constexpr support to `unique_ptr` in {cpp}20 mode.
*** `unique_ptr` constructors and operators that are not valid for the deleter or element type do
    not participate in overload resolution in {cpp}11 and later ({cpp}17's LWG 2801 and LWG 2905),
    so type traits give correct results.
*** Added a documentation chapter for `unique_ptr` ("Smart pointer unique_ptr" in the
    documentation).
*** `has_trivial_destructor_after_move` is now true for `unique_ptr` when the pointer type is
    trivially destructible and the deleter is a reference or has a trivial destructor after move.
    Containers such as `boost::container::vector` then do not destroy moved-from `unique_ptr`
    elements.
*** Added limited `hash_value` support for `unique_ptr`, so that it can be used with `boost::hash`
    and **Boost.Unordered**.
*** Added `make_unique_for_overwrite`, the {cpp}20 name of `make_unique_definit`.
*** Added the stream output operator (`operator<<`) for `unique_ptr`, without including `<iosfwd>`.
** A systematic, AI-assisted review of the library found and fixed many bugs that users did not
   report. The main types of bugs are:
*** Type traits: incorrect results of `is_convertible`, `is_constructible`,
    `is_copy_constructible`, `is_move_constructible`, `alignment_of`, `is_unsigned`,
    `is_nothrow_swappable` and the trivial and nothrow traits for abstract classes, arrays,
    functions, over-aligned types, POD types with deleted special members.
*** Exception safety: leaks in algorithms when a move assignment throws.
*** Sort and merge algorithms: stability bugs in `adaptive_sort` and `adaptive_merge`.
*** Iterators and swap: proxy iterators in `move_iterator`, `adl_move_iter_swap` and
    `adl_move_swap_ranges`.
*** `unique_ptr`: deleter checks, `get_deleter()` with reference deleters, `noexcept` conditions,
    and comparisons with `nullptr`.

   (boost_gh:pr[serialization,332]).
** Raised the archive library version to 21, so earlier versions of the library reject text and
   binary archives written by this one; archives written by earlier versions still load. The
   change stores at full width the enumerations whose underlying type is wider than `int`, which
   used to be truncated (boost_gh:issue[serialization,353]).
** Fixed the termination of the program when an XML input archive is destroyed at the end of its
   input, e.g. after a failed read, a regression of Boost 1.66 (boost_gh:issue[serialization,82],
   boost_gh:issue[serialization,99], boost_gh:issue[serialization,109]).
** Deprecated `<boost/serialization/std_variant.hpp>`, as `<boost/serialization/variant.hpp>`
   handles `std::variant` too, and removed `<boost/serialization/variant2.hpp>`, which was

** Added support for `std::filesystem::path`, except with GCC before 9, whose `<filesystem>` is
   unreliable (boost_gh:issue[serialization,337]).

   `BOOST_CLASS_VERSION` does for a class (boost_gh:issue[serialization,179]).

** Made `optional<T>` serializable when `T` is move-only (boost_gh:pr[serialization,330]).
** Made the alternatives of a `variant` load as container elements do, so that they no longer
   need a public default constructor (boost_gh:issue[serialization,338]).
** Made a `std::basic_string` with an allocator of its own, such as `std::pmr::string`,
   serializable with no declaration, in the same form as `std::string`

** Made public the `base_type` typedef of `version_type`, `class_id_type`, `object_id_type`,

** Added constructors which take the end of the input to `transform_width` and
   `remove_whitespace`. With them, a base64 decoder no longer reads past the end of an input whose
   length leaves a remainder of one when divided by four, nor `remove_whitespace` past one which

** Fixed an object saved through a pointer to its base class, across shared libraries, loading
   with its base part empty, a regression of Boost 1.84 (boost_gh:issue[serialization,329]).
** Fixed silent data loss when the same `variant` is serialized by value more than once

** Made the XML output archive write the closing tag of a complete document even when it is
   destroyed during stack unwinding (boost_gh:issue[serialization,188]).
** Fixed the loading from XML archives of a `std::wstring` with characters outside ASCII, which

** Fixed malformed escapes in wide XML archives, and the archive iterators `xml_escape`,
   `xml_unescape`, `transform_width` and `remove_whitespace` losing their state when copied
   (boost_gh:issue[serialization,229]).
** Fixed a leak and double frees in the cleanup after an exception interrupts a load: the object
   being loaded leaked, and objects an owning smart pointer had taken over were freed again. Note
