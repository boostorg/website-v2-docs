= Real-Time Vehicle Control Systems
:navtitle: Real-Time Vehicle Control

Our vehicles are becoming more and more computer systems, computer systems with wheels, wings, propellors, and many variations such as caterpillar tracks.

Real-time vehicle control and monitoring is an important and complex scenario for advanced pass:[C++] development. In this scenario software has to be developed that can be entrusted with the well-being of the vehicle's crew and passengers. In this scenario, we examine what libraries might prove to be valuable building blocks, what kind of architecture and control flow might be involved, and best-practices for safe systems.

With this high-tech control system in mind, let's examine the role individual Boost libraries might play.

== Simulate a PID Controller

Let's build a small, runnable vehicle speed-control simulation, showing the PID approach in action.

We'll model a vehicle that must accelerate to a target speed and maintain it, even when a hill introduces extra resistance. A PID controller adjusts the throttle, while we simulate the vehicle's motion over time.

The example demonstrate a useful separation of responsibilities:

* boost:numeric/odeint[] : integrates the vehicle's equations of motion.
* boost:atomic[] : safely publishes the target speed between a simulated supervisory controller and the control loop.

[source,cpp]
----

#include <boost/atomic.hpp>
#include <boost/numeric/odeint.hpp>
#include <iostream>

// State variables: position (m), speed (m/s).
using State = std::array<double, 2>;
using namespace boost::numeric::odeint;

// Simplified vehicle parameters.
constexpr double mass = 1500.0;          // Kg
constexpr double max_force = 5000.0;     // Newtons
constexpr double rolling_force = 180.0;  // Newtons
constexpr double drag_factor = 0.42;     // Newtons / (meters/second)^2
constexpr double gravity = 9.81;         // meters/second^2

// PID controller: output is throttle in the range [0 = none, 1 = max].
struct PID
{
    double kp = 0.025;
    double ki = 0.003;
    double kd = 0.002;

    double integral = 0.0;
    double previous_error = 0.0;

    double update(double target, double speed, double dt)
    {
        const double error = target - speed;

        // Limit the integral term to reduce integral windup.
        integral = std::clamp(integral + error * dt,
            -20.0, 20.0);

        const double derivative = (error - previous_error) / dt;
        previous_error = error;

        const double output =
            kp * error + ki * integral + kd * derivative;

        return std::clamp(output, 0.0, 1.0);
    }
};

// Vehicle equations of motion.
// The throttle and road slope remain constant during each step.
struct VehicleDynamics
{
    double throttle;
    double slope;

    void operator()(const State& x, State& dxdt, double /* time */) const
    {
        const double speed = x[1];

        const double traction = throttle * max_force;
        const double drag = drag_factor * speed * std::abs(speed);
        const double rolling = rolling_force * std::tanh(speed / 0.2);

        // Convert road slope (rise / horizontal distance) to
        // the component of gravity acting along the road.
        const double hill_force =
            mass * gravity * slope /
            std::sqrt(1.0 + slope * slope);

        const double acceleration =
            (traction - drag - rolling - hill_force) / mass;

        dxdt[0] = speed;         // Position derivative.
        dxdt[1] = acceleration;  // Speed derivative.
    }
};

int main()
{
    constexpr double dt = 0.01;       // 100 Hz control rate.
    constexpr int total_steps = 3000; // 30 simulated seconds.

    // Shared target speed, in metres per second.
    // Another thread could safely update this atomic value.
    boost::atomic<double> target_speed_mps{ 25.0 };

    PID pid;
    State vehicle{ 0.0, 0.0 }; // Initial position and speed.
    runge_kutta4<State> integrator;

    // Print an aligned telemetry table.
    std::cout << std::left
        << std::setw(10) << "Time (s)"
        << std::right
        << std::setw(14) << "Target (m/s)"
        << std::setw(14) << "Speed (m/s)"
        << std::setw(16) << "Position (m)"
        << std::setw(12) << "Throttle"
        << '\n';

    std::cout << std::string(66, '-') << '\n';
    std::cout << std::fixed << std::setprecision(2);

    bool target_changed = false;

    for (int step = 0; step < total_steps; ++step)
    {
        const double t = step * dt;

        // At 20 seconds, reduce the target speed to 18 m/s.
        if (t >= 20.0 && !target_changed)
        {
            target_speed_mps.store(
                18.0, boost::memory_order_relaxed);
            target_changed = true;
        }

        const double target =
            target_speed_mps.load(boost::memory_order_relaxed);

        // Compute throttle from the current speed error.
        const double throttle = pid.update(target, vehicle[1], dt);

        // Simulate a gradient section from 8 to 16 seconds.
        const double slope = (t >= 8.0 && t < 16.0) ? 0.3 : 0.0;

        // Integrate vehicle position and speed by one time step.
        VehicleDynamics dynamics{ throttle, slope };
        integrator.do_step(dynamics, vehicle, t, dt);

        // Display telemetry once per simulated second.
        if (step % 100 == 0)
        {
            std::cout << std::left
                << std::setw(10) << t
                << std::right
                << std::setw(14) << target
                << std::setw(14) << vehicle[1]
                << std::setw(16) << vehicle[0]
                << std::setw(12) << throttle
                << '\n';
        }
    }

    return 0;
}
----

Build with a C++17-capable compiler.

What to look for in the results:

* From 0 to 8 seconds, throttle increases the vehicle's speed toward 25 m/s.
* From 8 to 16 seconds, uphill resistance increases, so the controller should maintain a higher throttle to compensate, though momentum is a factor.
* At 20 seconds, the target drops to 18 m/s and there is no uphill. The controller reduces throttle, and the vehicle slows as drag and rolling resistance dissipate its momentum.

This is a simplified throttle-only controller, with no active braking, actuator delay, gear shifting, or traction limits.

== Footnotes

[#footnote1]
link:#footnote1-location[(1)]
In the tractor example, “Control law — PID/model” means that the software controlling things such as hydraulic valves, blade position, engine speed, or vehicle speed could use either a PID controller, a model-based controller, or a combination of the two. Suppose the tractor's blade is supposed to be at a particular height. The controller continuously compares 
desired blade height against actual blade height, the delta being treated as an error. A PID controller uses that error in three ways:

[cols="1,1,2",stripes=even,options="header",frame=none]
|===
| Part  | Meaning      | Intuition                                  
| **P** | Proportional | “How far away am I right now?”             
| **I** | Integral     | “How long have I been wrong?”              
| **D** | Derivative   | “How quickly am I approaching the target?” 
|===

The P component might say: "We're 10 cm low, so raise the blade substantially" and as the blade gets closer: "We're only 2 cm low, so raise it much more gently". The I component notices if, for example, the blade consistently stays 1 cm below the target because of hydraulic leakage or load. The D component notices that the blade is moving rapidly toward the target and reduces the command - to help prevent overshooting.
